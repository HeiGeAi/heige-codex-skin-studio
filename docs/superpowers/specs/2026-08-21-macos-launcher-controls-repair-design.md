# macOS 启动器打开、关闭与一键修复设计

## 目标

在现有双产品启动器中补齐三类明确操作：

1. 「打开皮肤」恢复对应产品最近一次使用的非原生主题。
2. 「关闭皮肤」仅暂停当前会话的皮肤，不删除主题、不改变最近主题，也不修改常驻偏好。
3. 「一键修复」对本机已安装的 Codex 与 WorkBuddy 执行强制干净重启，并在各自独立端口恢复最近主题。

## 交互

每张产品卡使用一个主按钮和一个次按钮。主按钮为产品强调色，标题统一为「打开 Codex 皮肤」或「打开 WorkBuddy 皮肤」。次按钮为系统中性色，标题为「关闭皮肤」。

底部操作区增加「一键修复」。修复期间禁用重复操作，完成后明确提示哪些产品已进入修复流程。未安装的产品自动跳过。

## 安全边界

所有操作继续经过稳定安装目录中的固定脚本和版本绑定 CLI，不接受任意命令或任意路径。Codex 固定使用 9341，WorkBuddy 固定使用 9342。关闭操作复用 `pause` 状态机。一键修复通过强制重启和 `launcher-apply` 延续命令恢复主题，不直接修改宿主资源，不接触 `app.asar`，不静默开启或关闭常驻。

## 失败处理

单产品打开或关闭失败时，错误显示在对应卡片中。一键修复逐个处理已安装产品，汇总成功和失败，不因一个产品失败而跳过另一个产品。所有底层错误先清理控制字符并截断后再展示。

## 验收

CLI 测试覆盖版本绑定、产品端口隔离、暂停语义、强制重启与最近主题恢复。脚本测试覆盖 Codex、WorkBuddy 和未知产品拒绝。原生源码测试覆盖新按钮、固定脚本和处理函数。最终构建通用二进制、生成可复现安装包、覆盖安装本机 APP，并通过完整发布门禁。
